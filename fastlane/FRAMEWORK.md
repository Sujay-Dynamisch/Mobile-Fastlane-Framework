# Mobile Distribution Framework (Fastlane)

A reusable, configuration-driven Fastlane setup that **builds**, **distributes** and **AI-tests** React Native (or any native Android / iOS) apps.

- **Android** → Firebase App Distribution (+ Firebase App Testing agent, AI-driven tests on real devices)
- **iOS** → TestFlight (App Store Connect) **and/or** Firebase App Distribution (Ad Hoc)
- One `Fastfile` for every project. Everything project-specific lives in **YAML config** and **environment variables**.

> **Status**
> | Platform | Status |
> |---|---|
> | Android | ✅ Verified end-to-end (build → upload → manual testers → AI tests → result) |
> | iOS → Firebase App Distribution | ✅ Verified on a Mac (build → Ad Hoc sign → upload → testers) |
> | iOS → TestFlight | ⚙️ Set up (App Store Connect app record + API key), **first upload not tested yet**. Follow [Step 6b](#step-6b--testflight-needs-the-api-key) and [Step 6c](#step-6c--verify-the-first-testflight-upload) |
> | iOS on CI (GitHub Actions) | ⚠️ Workflow ready, **not run yet** (needs the iOS repository secrets). See [section 15](#15-cicd-github-actions) |

## 1. What the framework does

| Capability | Android | iOS |
|---|---|---|
| Validate config before building (`doctor`) | ✅ | ✅ |
| Show resolved config without secrets (`info`) | ✅ | ✅ |
| Build release artifact | APK / AAB via Gradle | IPA via Xcode (`gym`) |
| Multiple environments (development / staging / uat / production) | ✅ | ✅ |
| Product flavors / custom Gradle tasks | ✅ | Schemes |
| Distribute | Firebase App Distribution (groups / emails) | TestFlight (internal / external groups) **or** Firebase App Distribution (Ad Hoc) |
| AI tests on real devices | Firebase App Testing agent | – |
| Automatic release notes | git commits / text / file | git commits / text / file |
| Build-number handling | – | `BUILD_NUMBER` or latest TestFlight + 1 |
| Code signing | Gradle `signingConfigs` | Xcode automatic signing **or** `match` |
| Teams / Slack webhook on success & failure | ✅ | ✅ |
| E-mail report of AI test results | ✅ | – |
| Production guard (branch, confirmation, CI-only) | ✅ | ✅ |

**Design rule:** the `Fastfile` and `lib/` are generic. To onboard a new app you change **only** `config/*.yml` and `.env` (or CI secrets).

## 2. Folder structure

```
<project root>/
├── Gemfile / Gemfile.lock        # fastlane 2.240.1 + firebase_app_distribution plugin 1.0.0
├── .env                          # local secrets (git-ignored)
├── .env.example                  # template of every variable the framework reads
├── .github/workflows/
│   ├── android-distribution.yml  # merged PR / "Run workflow" → Firebase
│   └── ios-distribution.yml      # "Run workflow" (or merged PR) → Firebase (Ad Hoc) and/or TestFlight
└── fastlane/
    ├── Fastfile                  # all lanes (generic – do not edit per project)
    ├── Appfile / Matchfile       # intentionally empty; identity comes from config
    ├── Pluginfile                # firebase_app_distribution plugin
    ├── FRAMEWORK.md              # this document
    ├── REACT_NATIVE_COMPATIBILITY.md
    ├── README.md                 # auto-generated by fastlane on every run (lane list)
    ├── release_notes.txt         # used when RELEASE_NOTES_FILE points to it
    ├── config/
    │   ├── environments.yml      # ★ project / platform / environment configuration
    │   ├── testing.yml           # ★ App Testing agent: on/off, devices, e-mail reports
    │   ├── test_case_ids.yml     # ★ which Firebase test cases to run
    │   └── profiles/             # ★ saved `fastlane setup` choices (committed)
    └── lib/
        ├── project_detector.rb   # detects flavors, build types, iOS schemes
        ├── project_bootstrap.rb  # `fastlane init_project` wizard
        ├── setup_wizard.rb       # `fastlane setup` wizard
        ├── profile_store.rb      # saved profiles + "last used" pointer
        ├── config_loader.rb      # loads YAML, expands ${ENV_VARS}, auto-detects app info
        ├── validation_helper.rb  # required values, files, Gradle task, production guard
        ├── artifact_helper.rb    # finds APK/AAB, copies a nicely named file into dist/
        ├── release_notes.rb      # git / manual / file release notes
        ├── notification_helper.rb# Teams / Slack webhooks
        ├── app_testing_agent.rb  # builds the test_devices / test_case_ids plugin options
        ├── test_result_parser.rb # turns the test outcome into report data
        └── email_notifier.rb     # SMTP e-mail with the AI test report
```

Generated output (git-ignored): `dist/` (named APK/IPA copies), `fastlane/report.xml`.

## 3. Prerequisites

> **React Native version?** The framework works with RN **0.60+**, including Expo after `npx expo prebuild`. RN 0.87.1 is verified on Android. See [REACT_NATIVE_COMPATIBILITY.md](REACT_NATIVE_COMPATIBILITY.md) for the version matrix, JDK/Ruby requirements and the notes for older templates.

**All platforms**
- Ruby (any version supported by fastlane 2.240; this repo runs Ruby 4.0 locally, Ruby 3.4 in CI) and Bundler
- Git (release notes are read from git history)
- Node.js + `npm ci` for React Native projects

**Android**
- JDK 17, Android SDK, a working `android/gradlew`
- Firebase project with the Android app registered
- Firebase CLI (`npm i -g firebase-tools`) – needed once to create `FIREBASE_TOKEN`

**iOS**
- macOS with Xcode and command-line tools (`xcode-select --install`)
- CocoaPods (installed through the Gemfile – the framework runs `pod install` itself)
- Apple Developer Program membership
- **Firebase (Ad Hoc):** an Apple ID signed in to Xcode that belongs to the team, plus registered tester devices
- **TestFlight:** the app created in App Store Connect, plus an App Store Connect API key (`.p8`, Key ID, Issuer ID). The same key also lets Firebase builds sign on CI, where no Apple ID is signed in to Xcode.
- Recent Xcode needs pod targets at iOS 15 or higher, and Firebase pods need modular headers. See the Podfile step in [section 11](#11-ios-setup-guide-any-project).

Install gems once per machine:

```bash
bundle config set path vendor/bundle
bundle install
```

## 4. Add the framework to a new project

1. **Copy files** from this repo into the new project root:
   - `fastlane/` (everything **except** secrets such as `firebase-service-account*.json`)
   - `Gemfile` lines for fastlane and the plugin (or the whole Gemfile if the project has none)
   - `.env.example`
   - `.github/workflows/*-distribution.yml` (optional)
2. **Add to `.gitignore`** (if not already present):
   ```gitignore
   .env
   .env.*
   !.env.example
   dist/
   vendor/bundle/
   **/fastlane/report.xml
   firebase-service-account*.json
   service-account*.json
   *.p8
   ```
3. `bundle install`
4. `cp .env.example .env` and fill in the values ([section 6](#6-environment-variables-and-secrets)).
5. Edit `fastlane/config/environments.yml`:
   - `project.name` (anything; used in artifact names and messages)
   - `android.environments.<env>.gradle_task` and `artifact.glob` (see [5.2](#52-android))
   - `ios.enabled: true` only on a Mac, set `workspace`, `scheme`, `bundle_identifier`
6. Android: set up Firebase ([section 7](#7-firebase-setup-android)). Optional AI tests: [section 8](#8-firebase-app-testing-agent-ai-tests) – or set `app_testing.enabled: false`.
7. Validate, then distribute:
   ```bash
   bundle exec fastlane android doctor environment:development
   bundle exec fastlane android distribute environment:development
   ```

Many values are **auto-detected** when left empty: app name (`app.json` → `strings.xml` → `package.json`), package/bundle id (`google-services.json` → `build.gradle`), Firebase app id (`google-services.json`), iOS workspace (`ios/*.xcworkspace`), iOS scheme (project name).

## 5. Configuration reference

Any string value can reference an environment variable as `${NAME}`. A value that is still `${NAME}` after loading (variable not set) is treated as **empty**.

### 5.1 `project`

```yaml
project:
  name: "MyApp"              # used in artifact names, e-mails, webhooks
  identifier: "myapp"
  organization: "Your Company"
  default_environment: "development"   # used when no environment: option and no APP_ENV
```

### 5.2 `android`

```yaml
android:
  enabled: true
  project_dir: "android"
  use_flavors: false            # true when build.gradle defines productFlavors
  build:
    clean_before_build: false   # run `gradle clean` first
    gradle_options: ""          # extra Gradle flags, e.g. "--no-daemon --stacktrace"
  environments:
    development:
      gradle_task: "assembleRelease"           # ★ source of truth – exact Gradle task
      artifact:
        type: "APK"                             # APK or AAB
        glob: "android/app/build/outputs/apk/release/*.apk"
      firebase:
        enabled: true
        app_id: "${FIREBASE_ANDROID_DEV_APP_ID}"   # empty → read from google-services.json
        groups: "${FIREBASE_ANDROID_DEV_GROUPS}"   # tester group aliases, comma-separated
        testers: ""                                 # or tester e-mails, comma-separated
      app_testing:
        enabled: true            # AI tests for this environment (overrides testing.yml)
      release_notes: { enabled: true, source: "git", commit_count: 10 }
      notifications: { teams: { enabled: false }, slack: { enabled: false } }
      safety: { ... }            # production only – see section 14
```

Common Gradle task / glob combinations:

| Project type | `gradle_task` | `artifact.glob` |
|---|---|---|
| No flavors, APK | `assembleRelease` | `android/app/build/outputs/apk/release/*.apk` |
| No flavors, AAB | `bundleRelease` | `android/app/build/outputs/bundle/release/*.aab` |
| Flavor `dev` | `assembleDevRelease` | `android/app/build/outputs/apk/dev/release/*.apk` |
| Flavor `prod`, AAB | `bundleProdRelease` | `android/app/build/outputs/bundle/prodRelease/*.aab` |
| Custom variant | e.g. `assembleInternalQaRelease` | matching output folder |

`doctor` checks that the task really exists (`gradlew tasks --all`).

### 5.3 `ios`

```yaml
ios:
  enabled: false                 # set true on the Mac
  project_dir: "ios"
  build:
    install_pods: true           # runs `pod install` (creates the .xcworkspace)
  signing:
    method: "automatic"          # automatic | match
    team_id: "${APPLE_TEAM_ID}"
    type: "appstore"             # match only
    readonly_in_ci: true         # match only: never create certs from CI
    update_project_signing: false# match only: set app target to manual signing (edits project.pbxproj)
  environments:
    development:
      workspace: "ios/MyApp.xcworkspace"
      scheme: "MyApp"        # must be a *Shared* scheme
      bundle_identifier: "com.example.myapp"
      export_method: "app-store"
      versioning:
        auto_increment_build_number: true
      testflight:
        enabled: true
        groups: []               # empty = internal testers only; names = external groups
        notify_external_testers: true
        skip_waiting_for_build_processing: true   # forced false when groups are set
      firebase:                  # `fastlane ios firebase` (Ad Hoc). Optional; omit or enabled: false to skip
        enabled: true            # keep false for production (production goes to TestFlight)
        export_method: "ad-hoc"
        app_id: "${FIREBASE_IOS_DEV_APP_ID}"
        groups: "${FIREBASE_IOS_DEV_GROUPS}"
        testers: ""
```

TestFlight and Firebase are independent. `ios doctor` reports each one as READY or NOT READY, and fails only if neither is configured.

Signing methods:

| `method` | What happens | You need |
|---|---|---|
| `automatic` (default) | `xcodebuild -allowProvisioningUpdates` creates/downloads the distribution certificate and profile. Uses the App Store Connect API key when it's set; otherwise (local `ios firebase` only) the Apple ID signed in to Xcode | API key with **Admin** (or App Manager + cloud-managed certificates) role, `APPLE_TEAM_ID`. Locally for Firebase: an Apple ID in Xcode that belongs to the team |
| `match` | `sync_code_signing` installs certs/profiles from a private Git repo | `MATCH_GIT_URL`, `MATCH_PASSWORD`, an initialised match repo (`bundle exec fastlane match appstore` once) |

### 5.4 Global sections

```yaml
notifications:        # release success/failure webhooks (defaults, overridable per environment)
  teams: { enabled: false, webhook_url: "${TEAMS_WEBHOOK_URL}" }
  slack: { enabled: false, webhook_url: "${SLACK_WEBHOOK_URL}" }
release_notes:        # defaults merged into each environment's release_notes
  enabled: true
  source: "git"       # git | manual | file
  commit_count: 10
  prefix: "Automated Mobile Distribution"
ci:
  build:
    clean_before_build: true     # iOS: clean archive when running on CI
security:
  production_requires_ci: false  # default for safety.require_ci
artifact:
  naming:
    enabled: true                # copy artifact to dist/ with a readable name
    pattern: "{project}-{environment}-v{version}-{build}.{extension}"   # also {commit}, {platform}
```

### 5.5 `testing.yml`

```yaml
app_testing:
  enabled: true      # global switch (environment app_testing.enabled overrides it)
  blocking: true     # true = wait for AI results; a failed test fails the lane
test_devices:        # each entry = one device run per test case
  - { model: "a54x", version: "34", locale: "en", orientation: "portrait" }
notifications:
  email:             # AI test report e-mail
    enabled: true
    notify_on_success: true
    notify_on_failure: true
    recipients: "${TEST_ALERT_EMAIL_RECIPIENTS}"
```

The file contains a commented catalog of available Firebase devices – uncomment entries to enable them. Per-environment overrides are possible under `android.environments.<env>.app_testing` (`test_devices`, `notifications.email`).

Precedence: environment `app_testing` → `testing.yml` → built-in default (Pixel 8 / API 34).

### 5.6 `test_case_ids.yml`

```yaml
test_case_ids:
  - first-test-case          # ID shown in Firebase Console → App Distribution → Test cases
```

Every ID listed runs on every configured device after each upload.

## 6. Environment variables and secrets

Local runs read `<project root>/.env` automatically. In CI, set them as secrets. **Never commit secrets** or put them in YAML.

### Android / Firebase

| Variable | Required | Purpose |
|---|---|---|
| `FIREBASE_TOKEN` | ✅ when AI tests are on | Refresh token from `firebase login:ci`. Takes priority over the service account. **Required for the App Testing agent** (see [16](#16-troubleshooting)) |
| `FIREBASE_SERVICE_CREDENTIALS_FILE` | ✅ if no token | Path to a service-account JSON (upload/distribution only) |
| `FIREBASE_ANDROID_<ENV>_APP_ID` | ✅ (or google-services.json) | `1:123…:android:abc…` per environment (`DEV`, `STAGING`, `UAT`, `PROD`) |
| `FIREBASE_ANDROID_<ENV>_GROUPS` | one of groups/testers | Tester group **aliases**, comma-separated |
| `FIREBASE_TEST_USERNAME` / `FIREBASE_TEST_PASSWORD` | optional | Login the AI agent uses when a test case signs in |

### iOS / App Store Connect

| Variable | Required | Purpose |
|---|---|---|
| `APP_STORE_CONNECT_KEY_ID` | ✅ | API key ID |
| `APP_STORE_CONNECT_ISSUER_ID` | ✅ (team keys) | Issuer ID |
| `APP_STORE_CONNECT_KEY_FILE` | one of file/content | Path to `AuthKey_XXXX.p8` |
| `APP_STORE_CONNECT_KEY_CONTENT` | one of file/content | Raw `.p8` content |
| `APPLE_TEAM_ID` | recommended | 10-character team ID |
| `MATCH_GIT_URL`, `MATCH_PASSWORD`, `MATCH_GIT_BRANCH` | `match` only | Certificates repo |

The `APP_STORE_CONNECT_*` variables are needed for **TestFlight only**. Firebase Ad Hoc builds don't need them on a Mac with an Apple ID signed in to Xcode.

### iOS / Firebase App Distribution

| Variable | Required | Purpose |
|---|---|---|
| `FIREBASE_IOS_<ENV>_APP_ID` | ✅ for `ios firebase` | `1:123…:ios:abc…` (Firebase Console → Project settings → your iOS app) |
| `FIREBASE_IOS_<ENV>_GROUPS` | one of groups/testers | Tester group **aliases**, comma-separated. If empty, the build uploads but goes to nobody |
| `FIREBASE_SERVICE_CREDENTIALS_FILE` / `FIREBASE_TOKEN` | ✅ | Same credentials as Android |

### Release metadata and notifications

| Variable | Purpose |
|---|---|
| `APP_ENV` | Default environment when `environment:` is not passed |
| `VERSION_NAME` | Version shown in names/messages; iOS also sets `MARKETING_VERSION` |
| `BUILD_NUMBER` | Build number (falls back to `GITHUB_RUN_NUMBER`); iOS sets `CURRENT_PROJECT_VERSION` |
| `RELEASE_NOTES` | Fixed release-notes text (overrides git) |
| `RELEASE_NOTES_FILE` | Path to a release-notes file (overrides everything) |
| `TEAMS_WEBHOOK_URL`, `SLACK_WEBHOOK_URL` | Webhooks |
| `SMTP_HOST`, `SMTP_PORT`, `SMTP_USERNAME`, `SMTP_PASSWORD`, `SMTP_FROM`, `TEST_ALERT_EMAIL_RECIPIENTS` | AI test report e-mail |

## 7. Firebase setup (Android)

1. **Register the app** in Firebase (package name must match `applicationId`, case-sensitive). Copy the App ID → `FIREBASE_ANDROID_<ENV>_APP_ID`.
2. **App Distribution → Testers & Groups**: create a group (e.g. `tester`) and add people. Put the group **alias** in `FIREBASE_ANDROID_<ENV>_GROUPS`.
3. **Authentication** – pick one:
   - **User token (recommended, required for AI tests)**
     ```bash
     firebase login:ci        # sign in with the account that opted in to App Testing
     ```
     Put the printed `1//…` token in `FIREBASE_TOKEN`. Treat it like a password.
   - **Service account (upload/distribution only)** – Google Cloud → IAM → Service accounts → create e.g. `fastlane-distribution`, roles:
     | Role | Why |
     |---|---|
     | Firebase App Distribution Admin | upload releases, manage testers/groups |
     | Firebase Test Lab Admin | device runs |
     | Gemini for Google Cloud User | App Testing agent runs on Gemini |
     | Service Usage Consumer | call enabled APIs |

     Create a JSON key → save as `fastlane/firebase-service-account-<name>.json` (git-ignored) → `FIREBASE_SERVICE_CREDENTIALS_FILE`.
4. **APIs enabled** in the Google Cloud project: Firebase App Distribution API, Cloud Testing API, **Cloud Tool Results API**, Gemini for Google Cloud API.
5. **Android signing**: this repo's `release` build type currently uses the **debug keystore** (fine for Firebase testers, **not** for Google Play). Configure a real `signingConfigs.release` before production/Play distribution.

## 8. Firebase App Testing agent (AI tests)

The App Testing agent (preview, powered by Gemini in Firebase) runs natural-language test cases on real devices after each upload.

**One-time setup**
1. Project owner opts in: Firebase Console → App Distribution → your app → **Test cases** / App Testing agent → accept the App Testing / Gemini in Firebase terms.
2. Create test cases in the console (goal, hint, success criteria per step). Copy each **test case ID** into `config/test_case_ids.yml`.
3. Choose devices in `config/testing.yml`.
4. Use `FIREBASE_TOKEN` of the account that opted in (service accounts are rejected with 403 – see [16](#16-troubleshooting)).
5. If a test logs in, set `FIREBASE_TEST_USERNAME` / `FIREBASE_TEST_PASSWORD`.

**Things to know**
- **Quota:** 200 tests / month / project during preview. *One test = one test case × one device.* 10 devices × 1 test case = 10 tests per distribution.
- **Timeout:** 5 minutes per test.
- **`FLAG_SECURE` blocks the agent** (it sees a blank screen). If your app enables `FLAG_SECURE` (e.g. after login), post-login steps will fail unless it is disabled for dev/staging builds.
- `blocking: false` uploads and starts the tests but does not wait for (or fail on) results.

## 9. Lanes and commands

Always run through Bundler from the project root. Pass the environment as `environment:<name>` (or set `APP_ENV`).

| Command | What it does |
|---|---|
| `bundle exec fastlane android doctor environment:staging` | Validates config, Gradle wrapper, Gradle task, artifact type, Firebase app id/groups/credentials, AI test setup |
| `bundle exec fastlane android info environment:staging` | Prints resolved config (no secrets) |
| `bundle exec fastlane android build environment:staging` | Gradle build → finds artifact → copies named file to `dist/` |
| `bundle exec fastlane android distribute environment:staging` | Full pipeline ([section 10](#10-how-a-distribution-run-works)) |
| `bundle exec fastlane android development` / `staging` / `uat` / `production` | Shortcuts for `distribute` |
| `bundle exec fastlane ios doctor environment:staging` | `pod install`, workspace, shared scheme, signing; reports **TestFlight** and **Firebase** readiness separately |
| `bundle exec fastlane ios info environment:staging` | Prints resolved iOS config |
| `bundle exec fastlane ios build environment:staging` | `pod install` → signing → build number → signed IPA in `dist/ios/<env>/` |
| `bundle exec fastlane ios distribute environment:staging` | Build + upload to TestFlight (+ external groups) |
| `bundle exec fastlane ios development` / `staging` / `uat` / `production` | Shortcuts for `distribute` |
| `bundle exec fastlane ios firebase environment:staging` | Ad Hoc IPA → Firebase App Distribution (no App Store Connect key needed on a Mac signed in to Xcode) |
| `bundle exec fastlane lanes` | List all lanes |

Android build options: `gradle_flags:"--stacktrace"` overrides `android.build.gradle_options` for one run.

### Interactive setup (CLI wizard)

| Command | What it does |
|---|---|
| `bundle exec fastlane init_project` | One-time wizard for a new project. Detects Android flavors and build types and iOS schemes, asks for environments and APK/AAB, Firebase and TestFlight options, and notifications, then writes `config/environments.yml` (the old file is kept as `.bak`). It also adds the missing keys to `.env.example`. |
| `bundle exec fastlane setup` | Per-run wizard. Choose **Use last setup**, **Use a saved setup**, **Create new**, **Edit** or **Delete**. A new setup asks for platform, environment, flavor, build type, APK/AAB, Gradle task and glob (derived, editable), build or distribute, testers, AI testing and release notes. It shows a summary, optionally saves the setup as a profile, then runs doctor and then build or distribute. |
| `bundle exec fastlane run_profile name:staging-aab` | Replays a saved profile with no prompts (works in CI). `dry_run:true` runs only doctor and info. |
| `bundle exec fastlane profiles` | Lists saved profiles. |

Profiles are committed in `fastlane/config/profiles/<name>.yml` and use the same keys as an `environments.yml` environment block. At run time they are deep-merged over that environment, so a profile overrides only what it sets. The "last used" pointer lives in the gitignored `fastlane/.setup_state.yml`. `setup` and `init_project` refuse to run in CI.

## 10. How a distribution run works

### Android (`android distribute`)

```
validate config ─► production guard ─► Gradle build ─► find APK/AAB ─► copy to dist/
      │
      ▼
release notes (file → text → git commits)
      │
      ▼
AI tests enabled AND groups/testers set?
  ├─ yes ─► 1) upload + distribute to manual testers (no test options)
  │         2) re-upload same APK (Firebase reuses the release: RELEASE_UNMODIFIED)
  │            + start AI tests, wait for results (blocking)
  └─ no  ─► single upload (+ AI tests if enabled) + distribute
      │
      ▼
AI test report e-mail (if enabled) ─► Teams/Slack success or failure ─► lane fails if tests failed
```

Why two uploads: the Firebase plugin only distributes to groups **after** AI tests pass. Splitting the call means manual testers always receive the build, while failing AI tests still fail the lane.

### iOS → Firebase (`ios firebase`)

```
validate config ─► production guard ─► Firebase enabled for this environment?
      │
      ▼
signing: automatic (-allowProvisioningUpdates; Apple ID in Xcode locally, API key on CI) | match
      │
      ▼
build number: BUILD_NUMBER / GITHUB_RUN_NUMBER (otherwise the Xcode project value)
      │
      ▼
pod install ─► build_app (export_method: ad-hoc) ─► dist/ios/<env>/<Project>-<env>-firebase.ipa
      │
      ▼
firebase_app_distribution (groups / testers, release notes) ─► Teams/Slack success or failure
```

Ad Hoc builds install only on devices that are in the provisioning profile, so register tester UDIDs before building (see [Step 6a](#step-6a--firebase-app-distribution-no-api-key-needed)).

### iOS → TestFlight (`ios distribute`)

```
validate config ─► production guard ─► App Store Connect API key
      │
      ▼
signing: automatic (-allowProvisioningUpdates + API key) | match (sync_code_signing)
      │
      ▼
build number: BUILD_NUMBER/GITHUB_RUN_NUMBER  or  latest TestFlight build + 1
      │
      ▼
pod install ─► build_app (CURRENT_PROJECT_VERSION / MARKETING_VERSION via xcargs) ─► IPA
      │
      ▼
upload_to_testflight (changelog = release notes; external groups if configured) ─► webhooks
```

The Xcode project is not modified for versioning: `Info.plist` uses `$(CURRENT_PROJECT_VERSION)` / `$(MARKETING_VERSION)`, which are overridden at build time.

## 11. iOS setup guide (any project)

Do these steps once per project, on a Mac. Values in `<angle brackets>` are specific to the project.

### Step 1 — Mac tooling
```bash
xcode-select --install                 # Xcode command-line tools
brew install cocoapods                 # or rely on the Gemfile's cocoapods
echo 'export LANG=en_US.UTF-8' >> ~/.zshrc && source ~/.zshrc   # CocoaPods requires UTF-8
bundle config set path vendor/bundle && bundle install
npm ci                                 # React Native projects
```
If `pod install` fails with `Could not find 'ffi'` after a Homebrew Ruby upgrade, run `brew reinstall cocoapods` or use `bundle exec pod install`.

### Step 2 — Copy the framework
Follow [section 4](#4-add-the-framework-to-a-new-project): copy `fastlane/`, the Gemfile lines, `.env.example`, and update `.gitignore`. Then:
```bash
bundle exec fastlane init_project      # interactive: writes fastlane/config/environments.yml
cp .env.example .env
```
`init_project` asks, for each environment, whether to upload to **TestFlight** and/or **Firebase (Ad Hoc)**. It never enables Firebase for production.

### Step 3 — Podfile (React Native + Firebase)
Inside `target '<App>' do`, if the app uses `@react-native-firebase/*`:
```ruby
$RNFirebaseDisableSPM = true                         # above the target block
pod 'GoogleUtilities', :modular_headers => true
pod 'FirebaseCore', :modular_headers => true
```
In `post_install`, after `react_native_post_install(...)`, add this so pods target at least iOS 15. Without it, the archive fails with *deployment target … supported range 15.0 to …*:
```ruby
installer.pods_project.targets.each do |target|
  target.build_configurations.each do |build_config|
    if build_config.build_settings['IPHONEOS_DEPLOYMENT_TARGET'].to_f < 15.0
      build_config.build_settings['IPHONEOS_DEPLOYMENT_TARGET'] = '15.0'
    end
  end
end
```
Then run `cd ios && pod install`, and check the simulator build with `npx react-native run-ios`.

### Step 4 — Xcode project
1. The scheme must be **Shared** (Product → Scheme → Manage Schemes → Shared), and `xcshareddata/` must be committed.
2. `Info.plist` must use `$(MARKETING_VERSION)` and `$(CURRENT_PROJECT_VERSION)`. `doctor` warns if they are hard-coded.
3. Recommended: add `ITSAppUsesNonExemptEncryption = NO` to `Info.plist`, unless the app uses custom encryption. Otherwise TestFlight builds wait on export compliance.

### Step 5 — Apple Developer account
1. Get a seat on the **paid** Apple Developer team that will own the app: Account Holder → App Store Connect → Users and Access → invite with **App Manager** or **Admin**.
2. Xcode → Settings → Accounts → sign in with that Apple ID.
3. Copy the **Team ID** (developer.apple.com → Membership) into `.env` as `APPLE_TEAM_ID`.

### Step 6a — Firebase App Distribution (no API key needed)
1. Firebase Console → add an **iOS app** with the exact bundle ID, and download `GoogleService-Info.plist` into `ios/`.
2. App Distribution → Testers & Groups → create a group, and note its **alias**.
3. Testers accept the invite on their iPhone and register their device. Then click **Export Apple UDIDs** and upload the file at developer.apple.com → Devices.
4. Fill in `.env`:
   ```
   FIREBASE_SERVICE_CREDENTIALS_FILE=/abs/path/service-account.json   # or FIREBASE_TOKEN
   FIREBASE_IOS_DEV_APP_ID=1:<project-number>:ios:<hash>
   FIREBASE_IOS_DEV_GROUPS=<group-alias>
   ```
5. Run:
   ```bash
   bundle exec fastlane ios doctor environment:development     # Firebase: READY
   bundle exec fastlane ios firebase environment:development
   ```
   On the first run, Xcode registers the App ID and creates the Ad Hoc profile for you. Builds install only on devices that were registered **before** the build, so rebuild after adding devices.

### Step 6b — TestFlight (needs the API key)
1. App Store Connect → **My Apps** → **+** → **New App**, using the same bundle ID.
2. App Store Connect → Users and Access → **Integrations** → App Store Connect API → **Team Keys** → **+**. Use the **App Manager** role, or **Admin** if automatic signing must create distribution certificates. Download the `.p8` file; it can only be downloaded once.
3. Fill in `.env`:
   ```
   APP_STORE_CONNECT_KEY_ID=<key id>
   APP_STORE_CONNECT_ISSUER_ID=<issuer id>
   APP_STORE_CONNECT_KEY_FILE=/abs/path/AuthKey_<key id>.p8     # or APP_STORE_CONNECT_KEY_CONTENT
   ```
4. Run:
   ```bash
   bundle exec fastlane ios doctor environment:development     # TestFlight: READY
   bundle exec fastlane ios development                        # build + upload to TestFlight
   ```
   No code or YAML change is needed. TestFlight works as soon as these three values are set.

### Step 6c — Verify the first TestFlight upload
The lane finishing is not the end: Apple still processes and checks the build. Before the first upload, check `Info.plist`:

| Check | Why |
|---|---|
| `ITSAppUsesNonExemptEncryption` = `NO` (if the app only uses standard HTTPS) | Otherwise every build waits in **Missing Compliance** |
| An `NS…UsageDescription` for every permission the app or its libraries use (camera, photo library read/add, location, Face ID, microphone…) | Missing purpose strings fail Apple's upload check (`ITMS-90683`) |
| App Store icon 1024×1024 **without transparency** | Icons with alpha are rejected (`ITMS-90717`) |
| `$(MARKETING_VERSION)` / `$(CURRENT_PROJECT_VERSION)` in `Info.plist` | Each upload needs a new build number |

After the upload:
1. The lane prints `iOS <env> build uploaded to TestFlight successfully.` and the success card is sent.
2. App Store Connect → **TestFlight**: the build goes **Processing** → **Ready to Test** (usually 10–30 minutes).
3. Answer **Missing Compliance** if it appears.
4. Add yourself under **Internal Testing**, install the build with the TestFlight app, and smoke-test it. Push notifications now use the **production** APNs environment.
5. Only then set the TestFlight status to ✅ in this document and in the project's own notes.

### Step 7 — Notifications (optional)
Set `TEAMS_WEBHOOK_URL` (a Power Automate *"When a Teams webhook request is received"* flow) and/or `SLACK_WEBHOOK_URL`. HTTP 202 only means the request was accepted. If no card appears, check the flow's run history.

### Step 8 — CI
CI machines have no Apple ID signed in to Xcode, so CI needs the **API key** for both TestFlight and Firebase iOS builds. Store every `.env` value as a CI secret (`APP_STORE_CONNECT_KEY_CONTENT` instead of the file path). Then:
1. Run the workflow manually (Actions → *iOS Distribution* → **Run workflow**) for `staging` with **Firebase** ticked.
2. Run it again with **TestFlight** ticked.
3. Only after both pass, set the repository variable `IOS_AUTO_DISTRIBUTE=true` (and `IOS_TESTFLIGHT=true` if merged PRs should go to TestFlight too). Until then, merged-PR runs show as **skipped**, which is expected.

### Done checklist
- [ ] `bundle exec fastlane ios doctor` passes
- [ ] Firebase: READY → `ios firebase` uploads and testers get the email
- [ ] TestFlight: READY → `ios development` shows a build in TestFlight, verified with [Step 6c](#step-6c--verify-the-first-testflight-upload)
- [ ] CI: manual workflow run passes for Firebase and for TestFlight
- [ ] Production: `ios production` only from `main`, with confirmation

## 12. Release notes, versioning, artifacts

**Release notes priority**
1. `RELEASE_NOTES_FILE` (env) – file contents
2. `RELEASE_NOTES` (env) – literal text
3. `release_notes.source` in config: `git` (last *n* commit subjects with prefix), `manual`, `file`

> ⚠️ The current `.env` sets `RELEASE_NOTES_FILE=fastlane/release_notes.txt`, so **git-based notes are never used locally** until that line is removed or the file is updated per release.

**Versioning**
- Android: `versionName` / `versionCode` stay in `android/app/build.gradle` (Firebase does not require unique version codes).
- iOS: build number from `BUILD_NUMBER` → `GITHUB_RUN_NUMBER` → latest TestFlight + 1 (`auto_increment_build_number`). Version from `VERSION_NAME` if set.

**Artifacts**: the original Gradle/Xcode output is never renamed; a copy named by `artifact.naming.pattern` goes to `dist/` (e.g. `dist/MyApp-development-vunknown-0.apk` – set `VERSION_NAME`/`BUILD_NUMBER` for meaningful names).

## 15. CI/CD (GitHub Actions)

Two workflows: *Android Distribution* and *iOS Distribution*. Each runs `doctor`, then distributes, and uploads the APK/IPA as a build artifact (kept 14 days).

**iOS channels**

| Channel | Manual run (checkbox) | Merged PR (repository variable) | Lane |
|---|---|---|---|
| Firebase App Distribution (Ad Hoc) | `firebase`, **on** by default | `IOS_FIREBASE`, default `true` | `ios firebase` |
| TestFlight | `testflight`, **off** by default | `IOS_TESTFLIGHT`, default `false` | `ios distribute` |

- Each selected channel builds its own IPA (Ad Hoc and App Store), so selecting both takes about twice as long.
- Production never goes to Firebase; the workflow skips it with a notice. Tick **TestFlight** for production.
- To turn TestFlight on, create the app in App Store Connect, then tick the box or set `IOS_TESTFLIGHT=true`. The signing secrets are the same for both channels.
- **The App Store Connect API key is required for both channels on CI.** Runners have no Apple ID signed in to Xcode, so signing goes through the key. Without it, the job fails early with a clear error. Locally on a Mac, `ios firebase` works without the key.

**When they run**

| Event | Android | iOS |
|---|---|---|
| Pull request into `main` **merged** | ✅ runs (environment: `ANDROID_AUTO_ENVIRONMENT`, default `development`) | Only if variable `IOS_AUTO_DISTRIBUTE=true` (environment: `IOS_AUTO_ENVIRONMENT`, default `staging`) |
| PR opened / updated / closed without merge | — | — |
| Direct push to `main` | — (protect `main` so changes arrive through PRs) | — |
| Only `*.md`, or `docs/**` changed | — | — |
| Actions → Run workflow (manual) | ✅ any environment | ✅ any environment |

Merged-PR builds use the PR title as release notes (`PR #12: …`) and the real target branch (`main`) for the production branch guard and the Teams card. Runs for the same environment queue instead of overlapping.

Repository **variables** (Settings → Secrets and variables → Actions → Variables): `ANDROID_AUTO_ENVIRONMENT`, `IOS_AUTO_DISTRIBUTE`, `IOS_AUTO_ENVIRONMENT`, `IOS_FIREBASE`, `IOS_TESTFLIGHT`, `VERSION_NAME` (all optional).

Secrets to create in the repository:

| Android | iOS |
|---|---|
| `FIREBASE_TOKEN` (needed for AI tests) — or — | `APP_STORE_CONNECT_KEY_ID` |
| `FIREBASE_SERVICE_ACCOUNT_JSON` (full JSON, written to a temp file) | `APP_STORE_CONNECT_ISSUER_ID` |
| `FIREBASE_ANDROID_<ENV>_APP_ID`, `FIREBASE_ANDROID_<ENV>_GROUPS` | `APP_STORE_CONNECT_KEY_CONTENT` (raw `.p8`, written to a temp file) |
| `FIREBASE_TEST_USERNAME`, `FIREBASE_TEST_PASSWORD` (optional) | `APPLE_TEAM_ID` |
| `TEAMS_WEBHOOK_URL`, `SMTP_HOST`, `SMTP_PORT`, `SMTP_USERNAME`, `SMTP_PASSWORD`, `SMTP_FROM`, `TEST_ALERT_EMAIL_RECIPIENTS` (optional) | `MATCH_GIT_URL`, `MATCH_GIT_BRANCH`, `MATCH_PASSWORD` (match only), `TEAMS_WEBHOOK_URL` (optional) |
| | **Firebase channel:** `FIREBASE_SERVICE_ACCOUNT_JSON` (or `FIREBASE_TOKEN`), `FIREBASE_IOS_<ENV>_APP_ID`, `FIREBASE_IOS_<ENV>_GROUPS` (`DEV`, `STAGING`, `UAT`) |

Repository variable `VERSION_NAME` is optional. `GITHUB_RUN_NUMBER` is used as the build number automatically.

## 16. Troubleshooting

| Symptom | Cause / fix |
|---|---|
| `403 PERMISSION_DENIED` → *"Firebase App Testing Agent test execution failed: Invalid request"* | The App Testing agent rejects **service accounts**, even with every IAM role. Use `FIREBASE_TOKEN` from `firebase login:ci` with the account that opted in. Also confirm the project owner opted in and the Tool Results API is enabled. |
| Manual testers did not receive the build | Group alias in `FIREBASE_ANDROID_<ENV>_GROUPS` must match the alias in Firebase exactly. With AI tests on, the framework distributes first (see section 10). |
| `Test Case <id> not found` | ID in `test_case_ids.yml` must match the console ID and belong to the same Firebase app. |
| AI test fails after login / sees blank screen | `FLAG_SECURE` is enabled in the app for that screen. |
| AI test quota exceeded | 200 tests/month; reduce devices in `testing.yml` or test cases. |
| `Gradle task 'X' was not found` | Fix `gradle_task` in `environments.yml` (exact task name, flavors included). |
| `No APK artifact found` | `artifact.glob` does not match the Gradle output folder. |
| `Missing required configuration: …` | The YAML value is empty or the referenced `${ENV_VAR}` is not set. |
| `iOS lanes require macOS with Xcode installed` | Expected on Windows/Linux. |
| `iOS workspace … does not exist` | `pod install` failed or `install_pods: false`; run `cd ios && bundle exec pod install`. |
| `iOS scheme '…' was not found` | Mark the scheme as **Shared** in Xcode and commit `xcshareddata`. |
| `⏩ No testers or groups passed in` (iOS Firebase) | Not an error: the build uploaded but went to nobody. Set `FIREBASE_IOS_<ENV>_GROUPS`. |
| Tester can't install an iOS Firebase build | Their device isn't in the Ad Hoc profile. Register the UDID, then rebuild. |
| Archive: *deployment target … supported range 15.0 to …* | Add the Podfile `post_install` deployment-target fix ([11, step 3](#11-ios-setup-guide-any-project)). |
| *FirebaseCoreInternal depends upon GoogleUtilities, which does not define modules* | Add the `modular_headers` pods ([11, step 3](#11-ios-setup-guide-any-project)). |
| `Missing required configuration: APP_STORE_CONNECT_KEY_ID` | A TestFlight lane ran without the API key. Use `ios firebase` or add the key. |
| Teams HTTP 202 but no card | The flow accepted the request but failed later. Check the Power Automate run history (expired connection, owner left the chat, flow off). |
| TestFlight: *bundle version already used* | Set `BUILD_NUMBER` or keep `auto_increment_build_number: true`. |
| TestFlight build stuck on **Missing Compliance** | Answer the encryption question in App Store Connect, or add `ITSAppUsesNonExemptEncryption` to `Info.plist`. |
| `ITMS-90683: Missing purpose string` | Add the named `NS…UsageDescription` key to `Info.plist`. |
| `No suitable application records were found` | Create the app in App Store Connect, or fix `bundle_identifier` so it matches the app record exactly. |
| App Store Connect HTTP 401 / *credentials are missing or invalid* | Wrong Key ID / Issuer ID, revoked key, or a `.p8` that belongs to another key. |
| iOS workflow run shows **skipped** | Merged PRs need the variable `IOS_AUTO_DISTRIBUTE=true`. Run it manually until CI is verified. |
| Email report not received | Check `SMTP_*`, `TEST_ALERT_EMAIL_RECIPIENTS`, and `notifications.email.enabled` in `testing.yml`. Errors are logged, not fatal. |
| Local `gcloud` fails with "Python was not found" | Install Python or use the Cloud Console; not needed by the framework. |
