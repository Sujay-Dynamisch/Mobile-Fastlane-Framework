# Mobile Distribution Framework (Fastlane)

A reusable, configuration-driven Fastlane setup that **builds**, **distributes** and **AI-tests** React Native (or any native Android / iOS) apps.

- **Android** → Firebase App Distribution (+ Firebase App Testing agent, AI-driven tests on real devices)
- **iOS** → TestFlight (App Store Connect)
- One `Fastfile` for every project. Everything project-specific lives in **YAML config** and **environment variables**.

> **Status**
> | Platform | Status |
> |---|---|
> | Android | ✅ Verified end-to-end (build → upload → manual testers → AI tests → result) |
> | iOS | ⚠️ Implemented and reviewed, **not yet run on a Mac**. Follow [iOS first-run checklist](#11-ios-first-run-checklist-mac) |

## 1. What the framework does

| Capability | Android | iOS |
|---|---|---|
| Validate config before building (`doctor`) | ✅ | ✅ |
| Show resolved config without secrets (`info`) | ✅ | ✅ |
| Build release artifact | APK / AAB via Gradle | IPA via Xcode (`gym`) |
| Multiple environments (development / staging / uat / production) | ✅ | ✅ |
| Product flavors / custom Gradle tasks | ✅ | Schemes |
| Distribute | Firebase App Distribution (groups / emails) | TestFlight (internal / external groups) |
| AI tests on real devices | Firebase App Testing agent | – |
| Automatic release notes | git commits / text / file | git commits / text / file |
| Build-number handling | – | `BUILD_NUMBER` or latest TestFlight + 1 |
| Code signing | Gradle `signingConfigs` | Xcode automatic signing **or** `match` |
| Teams / Slack webhook on success & failure | ✅ | ✅ |
| E-mail report of AI test results | ✅ | – |
| Production guard (branch, confirmation, CI-only) | ✅ | ✅ |

**Design rule:** the `Fastfile` and `lib/` are generic. To onboard a new app you change **only** `config/*.yml` and `.env` (or CI secrets).

## 2. Folder structure

```
<project root>/
├── Gemfile / Gemfile.lock        # fastlane 2.240.1 + firebase_app_distribution plugin 1.0.0
├── .env                          # local secrets (git-ignored)
├── .env.example                  # template of every variable the framework reads
├── .github/workflows/
│   ├── android-distribution.yml  # manual "Run workflow" → Firebase
│   └── ios-distribution.yml      # manual "Run workflow" → TestFlight
└── fastlane/
    ├── Fastfile                  # all lanes (generic – do not edit per project)
    ├── Appfile / Matchfile       # intentionally empty; identity comes from config
    ├── Pluginfile                # firebase_app_distribution plugin
    ├── FRAMEWORK.md              # this document
    ├── README.md                 # auto-generated by fastlane on every run (lane list)
    ├── release_notes.txt         # used when RELEASE_NOTES_FILE points to it
    ├── config/
    │   ├── environments.yml      # ★ project / platform / environment configuration
    │   ├── testing.yml           # ★ App Testing agent: on/off, devices, e-mail reports
    │   └── test_case_ids.yml     # ★ which Firebase test cases to run
    └── lib/
        ├── config_loader.rb      # loads YAML, expands ${ENV_VARS}, auto-detects app info
        ├── validation_helper.rb  # required values, files, Gradle task, production guard
        ├── artifact_helper.rb    # finds APK/AAB, copies a nicely named file into dist/
        ├── release_notes.rb      # git / manual / file release notes
        ├── notification_helper.rb# Teams / Slack webhooks
        ├── app_testing_agent.rb  # builds the test_devices / test_case_ids plugin options
        ├── test_result_parser.rb # turns the test outcome into report data
        └── email_notifier.rb     # SMTP e-mail with the AI test report
```

Generated output (git-ignored): `dist/` (named APK/IPA copies), `fastlane/report.xml`.

## 3. Prerequisites

**All platforms**
- Ruby (any version supported by fastlane 2.240; this repo runs Ruby 4.0 locally, Ruby 3.4 in CI) and Bundler
- Git (release notes are read from git history)
- Node.js + `npm ci` for React Native projects

**Android**
- JDK 17, Android SDK, a working `android/gradlew`
- Firebase project with the Android app registered
- Firebase CLI (`npm i -g firebase-tools`) – needed once to create `FIREBASE_TOKEN`

**iOS**
- macOS with Xcode and command-line tools (`xcode-select --install`)
- CocoaPods (installed through the Gemfile – the framework runs `pod install` itself)
- Apple Developer Program membership, App created in App Store Connect
- App Store Connect API key (`.p8`, Key ID, Issuer ID)

Install gems once per machine:

```bash
bundle config set path vendor/bundle
bundle install
```

## 4. Add the framework to a new project

1. **Copy files** from this repo into the new project root:
   - `fastlane/` (everything **except** secrets such as `firebase-service-account*.json`)
   - `Gemfile` lines for fastlane and the plugin (or the whole Gemfile if the project has none)
   - `.env.example`
   - `.github/workflows/*-distribution.yml` (optional)
2. **Add to `.gitignore`** (if not already present):
   ```gitignore
   .env
   .env.*
   !.env.example
   dist/
   vendor/bundle/
   **/fastlane/report.xml
   firebase-service-account*.json
   service-account*.json
   *.p8
   ```
3. `bundle install`
4. `cp .env.example .env` and fill in the values ([section 6](#6-environment-variables-and-secrets)).
5. Edit `fastlane/config/environments.yml`:
   - `project.name` (anything; used in artifact names and messages)
   - `android.environments.<env>.gradle_task` and `artifact.glob` (see [5.2](#52-android))
   - `ios.enabled: true` only on a Mac, set `workspace`, `scheme`, `bundle_identifier`
6. Android: set up Firebase ([section 7](#7-firebase-setup-android)). Optional AI tests: [section 8](#8-firebase-app-testing-agent-ai-tests) – or set `app_testing.enabled: false`.
7. Validate, then distribute:
   ```bash
   bundle exec fastlane android doctor environment:development
   bundle exec fastlane android distribute environment:development
   ```

Many values are **auto-detected** when left empty: app name (`app.json` → `strings.xml` → `package.json`), package/bundle id (`google-services.json` → `build.gradle`), Firebase app id (`google-services.json`), iOS workspace (`ios/*.xcworkspace`), iOS scheme (project name).

## 5. Configuration reference

Any string value can reference an environment variable as `${NAME}`. A value that is still `${NAME}` after loading (variable not set) is treated as **empty**.

### 5.1 `project`

```yaml
project:
  name: "MyApp"              # used in artifact names, e-mails, webhooks
  identifier: "myapp"
  organization: "Your Company"
  default_environment: "development"   # used when no environment: option and no APP_ENV
```

### 5.2 `android`

```yaml
android:
  enabled: true
  project_dir: "android"
  use_flavors: false            # true when build.gradle defines productFlavors
  build:
    clean_before_build: false   # run `gradle clean` first
    gradle_options: ""          # extra Gradle flags, e.g. "--no-daemon --stacktrace"
  environments:
    development:
      gradle_task: "assembleRelease"           # ★ source of truth – exact Gradle task
      artifact:
        type: "APK"                             # APK or AAB
        glob: "android/app/build/outputs/apk/release/*.apk"
      firebase:
        enabled: true
        app_id: "${FIREBASE_ANDROID_DEV_APP_ID}"   # empty → read from google-services.json
        groups: "${FIREBASE_ANDROID_DEV_GROUPS}"   # tester group aliases, comma-separated
        testers: ""                                 # or tester e-mails, comma-separated
      app_testing:
        enabled: true            # AI tests for this environment (overrides testing.yml)
      release_notes: { enabled: true, source: "git", commit_count: 10 }
      notifications: { teams: { enabled: false }, slack: { enabled: false } }
      safety: { ... }            # production only – see section 14
```

Common Gradle task / glob combinations:

| Project type | `gradle_task` | `artifact.glob` |
|---|---|---|
| No flavors, APK | `assembleRelease` | `android/app/build/outputs/apk/release/*.apk` |
| No flavors, AAB | `bundleRelease` | `android/app/build/outputs/bundle/release/*.aab` |
| Flavor `dev` | `assembleDevRelease` | `android/app/build/outputs/apk/dev/release/*.apk` |
| Flavor `prod`, AAB | `bundleProdRelease` | `android/app/build/outputs/bundle/prodRelease/*.aab` |
| Custom variant | e.g. `assembleInternalQaRelease` | matching output folder |

`doctor` checks that the task really exists (`gradlew tasks --all`).

### 5.3 `ios`

```yaml
ios:
  enabled: false                 # set true on the Mac
  project_dir: "ios"
  build:
    install_pods: true           # runs `pod install` (creates the .xcworkspace)
  signing:
    method: "automatic"          # automatic | match
    team_id: "${APPLE_TEAM_ID}"
    type: "appstore"             # match only
    readonly_in_ci: true         # match only: never create certs from CI
    update_project_signing: false# match only: set app target to manual signing (edits project.pbxproj)
  environments:
    development:
      workspace: "ios/MyApp.xcworkspace"
      scheme: "MyApp"        # must be a *Shared* scheme
      bundle_identifier: "com.example.myapp"
      export_method: "app-store"
      versioning:
        auto_increment_build_number: true
      testflight:
        enabled: true
        groups: []               # empty = internal testers only; names = external groups
        notify_external_testers: true
        skip_waiting_for_build_processing: true   # forced false when groups are set
```

Signing methods:

| `method` | What happens | You need |
|---|---|---|
| `automatic` (default) | `xcodebuild -allowProvisioningUpdates` with the App Store Connect API key creates/downloads the distribution certificate and profile | API key with **Admin** (or App Manager + cloud-managed certificates) role, `APPLE_TEAM_ID` |
| `match` | `sync_code_signing` installs certs/profiles from a private Git repo | `MATCH_GIT_URL`, `MATCH_PASSWORD`, an initialised match repo (`bundle exec fastlane match appstore` once) |

### 5.4 Global sections

```yaml
notifications:        # release success/failure webhooks (defaults, overridable per environment)
  teams: { enabled: false, webhook_url: "${TEAMS_WEBHOOK_URL}" }
  slack: { enabled: false, webhook_url: "${SLACK_WEBHOOK_URL}" }
release_notes:        # defaults merged into each environment's release_notes
  enabled: true
  source: "git"       # git | manual | file
  commit_count: 10
  prefix: "Automated Mobile Distribution"
ci:
  build:
    clean_before_build: true     # iOS: clean archive when running on CI
security:
  production_requires_ci: false  # default for safety.require_ci
artifact:
  naming:
    enabled: true                # copy artifact to dist/ with a readable name
    pattern: "{project}-{environment}-v{version}-{build}.{extension}"   # also {commit}, {platform}
```

### 5.5 `testing.yml`

```yaml
app_testing:
  enabled: true      # global switch (environment app_testing.enabled overrides it)
  blocking: true     # true = wait for AI results; a failed test fails the lane
test_devices:        # each entry = one device run per test case
  - { model: "a54x", version: "34", locale: "en", orientation: "portrait" }
notifications:
  email:             # AI test report e-mail
    enabled: true
    notify_on_success: true
    notify_on_failure: true
    recipients: "${TEST_ALERT_EMAIL_RECIPIENTS}"
```

The file contains a commented catalog of available Firebase devices – uncomment entries to enable them. Per-environment overrides are possible under `android.environments.<env>.app_testing` (`test_devices`, `notifications.email`).

Precedence: environment `app_testing` → `testing.yml` → built-in default (Pixel 8 / API 34).

### 5.6 `test_case_ids.yml`

```yaml
test_case_ids:
  - first-test-case          # ID shown in Firebase Console → App Distribution → Test cases
```

Every ID listed runs on every configured device after each upload.

## 6. Environment variables and secrets

Local runs read `<project root>/.env` automatically. In CI, set them as secrets. **Never commit secrets** or put them in YAML.

### Android / Firebase

| Variable | Required | Purpose |
|---|---|---|
| `FIREBASE_TOKEN` | ✅ when AI tests are on | Refresh token from `firebase login:ci`. Takes priority over the service account. **Required for the App Testing agent** (see [16](#16-troubleshooting)) |
| `FIREBASE_SERVICE_CREDENTIALS_FILE` | ✅ if no token | Path to a service-account JSON (upload/distribution only) |
| `FIREBASE_ANDROID_<ENV>_APP_ID` | ✅ (or google-services.json) | `1:123…:android:abc…` per environment (`DEV`, `STAGING`, `UAT`, `PROD`) |
| `FIREBASE_ANDROID_<ENV>_GROUPS` | one of groups/testers | Tester group **aliases**, comma-separated |
| `FIREBASE_TEST_USERNAME` / `FIREBASE_TEST_PASSWORD` | optional | Login the AI agent uses when a test case signs in |

### iOS / App Store Connect

| Variable | Required | Purpose |
|---|---|---|
| `APP_STORE_CONNECT_KEY_ID` | ✅ | API key ID |
| `APP_STORE_CONNECT_ISSUER_ID` | ✅ (team keys) | Issuer ID |
| `APP_STORE_CONNECT_KEY_FILE` | one of file/content | Path to `AuthKey_XXXX.p8` |
| `APP_STORE_CONNECT_KEY_CONTENT` | one of file/content | Raw `.p8` content |
| `APPLE_TEAM_ID` | recommended | 10-character team ID |
| `MATCH_GIT_URL`, `MATCH_PASSWORD`, `MATCH_GIT_BRANCH` | `match` only | Certificates repo |

### Release metadata and notifications

| Variable | Purpose |
|---|---|
| `APP_ENV` | Default environment when `environment:` is not passed |
| `VERSION_NAME` | Version shown in names/messages; iOS also sets `MARKETING_VERSION` |
| `BUILD_NUMBER` | Build number (falls back to `GITHUB_RUN_NUMBER`); iOS sets `CURRENT_PROJECT_VERSION` |
| `RELEASE_NOTES` | Fixed release-notes text (overrides git) |
| `RELEASE_NOTES_FILE` | Path to a release-notes file (overrides everything) |
| `TEAMS_WEBHOOK_URL`, `SLACK_WEBHOOK_URL` | Webhooks |
| `SMTP_HOST`, `SMTP_PORT`, `SMTP_USERNAME`, `SMTP_PASSWORD`, `SMTP_FROM`, `TEST_ALERT_EMAIL_RECIPIENTS` | AI test report e-mail |

## 7. Firebase setup (Android)

1. **Register the app** in Firebase (package name must match `applicationId`, case-sensitive). Copy the App ID → `FIREBASE_ANDROID_<ENV>_APP_ID`.
2. **App Distribution → Testers & Groups**: create a group (e.g. `tester`) and add people. Put the group **alias** in `FIREBASE_ANDROID_<ENV>_GROUPS`.
3. **Authentication** – pick one:
   - **User token (recommended, required for AI tests)**
     ```bash
     firebase login:ci        # sign in with the account that opted in to App Testing
     ```
     Put the printed `1//…` token in `FIREBASE_TOKEN`. Treat it like a password.
   - **Service account (upload/distribution only)** – Google Cloud → IAM → Service accounts → create e.g. `fastlane-distribution`, roles:
     | Role | Why |
     |---|---|
     | Firebase App Distribution Admin | upload releases, manage testers/groups |
     | Firebase Test Lab Admin | device runs |
     | Gemini for Google Cloud User | App Testing agent runs on Gemini |
     | Service Usage Consumer | call enabled APIs |

     Create a JSON key → save as `fastlane/firebase-service-account-<name>.json` (git-ignored) → `FIREBASE_SERVICE_CREDENTIALS_FILE`.
4. **APIs enabled** in the Google Cloud project: Firebase App Distribution API, Cloud Testing API, **Cloud Tool Results API**, Gemini for Google Cloud API.
5. **Android signing**: this repo's `release` build type currently uses the **debug keystore** (fine for Firebase testers, **not** for Google Play). Configure a real `signingConfigs.release` before production/Play distribution.

## 8. Firebase App Testing agent (AI tests)

The App Testing agent (preview, powered by Gemini in Firebase) runs natural-language test cases on real devices after each upload.

**One-time setup**
1. Project owner opts in: Firebase Console → App Distribution → your app → **Test cases** / App Testing agent → accept the App Testing / Gemini in Firebase terms.
2. Create test cases in the console (goal, hint, success criteria per step). Copy each **test case ID** into `config/test_case_ids.yml`.
3. Choose devices in `config/testing.yml`.
4. Use `FIREBASE_TOKEN` of the account that opted in (service accounts are rejected with 403 – see [16](#16-troubleshooting)).
5. If a test logs in, set `FIREBASE_TEST_USERNAME` / `FIREBASE_TEST_PASSWORD`.

**Things to know**
- **Quota:** 200 tests / month / project during preview. *One test = one test case × one device.* 10 devices × 1 test case = 10 tests per distribution.
- **Timeout:** 5 minutes per test.
- **`FLAG_SECURE` blocks the agent** (it sees a blank screen). If your app sets `FLAG_SECURE` on any screen, steps on that screen will fail – disable it for dev/staging builds.
- `blocking: false` uploads and starts the tests but does not wait for (or fail on) results.

## 9. Lanes and commands

Always run through Bundler from the project root. Pass the environment as `environment:<name>` (or set `APP_ENV`).

| Command | What it does |
|---|---|
| `bundle exec fastlane android doctor environment:staging` | Validates config, Gradle wrapper, Gradle task, artifact type, Firebase app id/groups/credentials, AI test setup |
| `bundle exec fastlane android info environment:staging` | Prints resolved config (no secrets) |
| `bundle exec fastlane android build environment:staging` | Gradle build → finds artifact → copies named file to `dist/` |
| `bundle exec fastlane android distribute environment:staging` | Full pipeline ([section 10](#10-how-a-distribution-run-works)) |
| `bundle exec fastlane android development` / `staging` / `uat` / `production` | Shortcuts for `distribute` |
| `bundle exec fastlane ios doctor environment:staging` | `pod install`, workspace, shared scheme, signing inputs, API key |
| `bundle exec fastlane ios info environment:staging` | Prints resolved iOS config |
| `bundle exec fastlane ios build environment:staging` | `pod install` → signing → build number → signed IPA in `dist/ios/<env>/` |
| `bundle exec fastlane ios distribute environment:staging` | Build + upload to TestFlight (+ external groups) |
| `bundle exec fastlane ios development` / `staging` / `uat` / `production` | Shortcuts for `distribute` |
| `bundle exec fastlane lanes` | List all lanes |

Android build options: `gradle_flags:"--stacktrace"` overrides `android.build.gradle_options` for one run.

## 10. How a distribution run works

### Android (`android distribute`)

```
validate config ─► production guard ─► Gradle build ─► find APK/AAB ─► copy to dist/
      │
      ▼
release notes (file → text → git commits)
      │
      ▼
AI tests enabled AND groups/testers set?
  ├─ yes ─► 1) upload + distribute to manual testers (no test options)
  │         2) re-upload same APK (Firebase reuses the release: RELEASE_UNMODIFIED)
  │            + start AI tests, wait for results (blocking)
  └─ no  ─► single upload (+ AI tests if enabled) + distribute
      │
      ▼
AI test report e-mail (if enabled) ─► Teams/Slack success or failure ─► lane fails if tests failed
```

Why two uploads: the Firebase plugin only distributes to groups **after** AI tests pass. Splitting the call means manual testers always receive the build, while failing AI tests still fail the lane.

### iOS (`ios distribute`)

```
validate config ─► production guard ─► App Store Connect API key
      │
      ▼
signing: automatic (-allowProvisioningUpdates + API key) | match (sync_code_signing)
      │
      ▼
build number: BUILD_NUMBER/GITHUB_RUN_NUMBER  or  latest TestFlight build + 1
      │
      ▼
pod install ─► build_app (CURRENT_PROJECT_VERSION / MARKETING_VERSION via xcargs) ─► IPA
      │
      ▼
upload_to_testflight (changelog = release notes; external groups if configured) ─► webhooks
```

The Xcode project is not modified for versioning: `Info.plist` uses `$(CURRENT_PROJECT_VERSION)` / `$(MARKETING_VERSION)`, which are overridden at build time.

## 11. iOS first-run checklist (Mac)

1. `bundle install` and `npm ci` on the Mac.
2. In `fastlane/config/environments.yml` set `ios.enabled: true`.
3. In Xcode, make sure the `MyApp` scheme is **Shared** (Product → Scheme → Manage Schemes → Shared). It already exists at `ios/MyApp.xcodeproj/xcshareddata/xcschemes/MyApp.xcscheme`.
4. App Store Connect: create the app with bundle id `com.example.myapp`; create an API key (Users and Access → Integrations → App Store Connect API, role **Admin** for automatic signing).
5. `.env` on the Mac:
   ```
   APPLE_TEAM_ID=XXXXXXXXXX
   APP_STORE_CONNECT_KEY_ID=...
   APP_STORE_CONNECT_ISSUER_ID=...
   APP_STORE_CONNECT_KEY_FILE=/absolute/path/AuthKey_XXXX.p8
   ```
6. Run, in order:
   ```bash
   bundle exec fastlane ios doctor environment:development
   bundle exec fastlane ios build  environment:development      # produces dist/ios/development/*.ipa
   bundle exec fastlane ios distribute environment:development
   ```
7. If signing fails with automatic signing, either open the project in Xcode once (Signing & Capabilities → select the team), or switch to `match`.

Known iOS considerations to verify on the first run:
- `pod install` runs inside the lane; the workspace `ios/MyApp.xcworkspace` does not exist until then.
- The first TestFlight upload of a new app needs export-compliance info in App Store Connect (or `ITSAppUsesNonExemptEncryption` in `Info.plist`).
- `ios build` alone (without `distribute`) also needs the API key, because it prepares signing and the build number.

## 12. Release notes, versioning, artifacts

**Release notes priority**
1. `RELEASE_NOTES_FILE` (env) – file contents
2. `RELEASE_NOTES` (env) – literal text
3. `release_notes.source` in config: `git` (last *n* commit subjects with prefix), `manual`, `file`

> ⚠️ The current `.env` sets `RELEASE_NOTES_FILE=fastlane/release_notes.txt`, so **git-based notes are never used locally** until that line is removed or the file is updated per release.

**Versioning**
- Android: `versionName` / `versionCode` stay in `android/app/build.gradle` (Firebase does not require unique version codes).
- iOS: build number from `BUILD_NUMBER` → `GITHUB_RUN_NUMBER` → latest TestFlight + 1 (`auto_increment_build_number`). Version from `VERSION_NAME` if set.

**Artifacts**: the original Gradle/Xcode output is never renamed; a copy named by `artifact.naming.pattern` goes to `dist/` (e.g. `dist/MyApp-development-vunknown-0.apk` – set `VERSION_NAME`/`BUILD_NUMBER` for meaningful names).

## 13. Notifications

| Type | Where configured | When |
|---|---|---|
| Teams / Slack webhook | `notifications` in `environments.yml` (global + per environment) | Every distribution success and failure (also uncaught lane errors) |
| AI test report e-mail (HTML + text) | `notifications.email` in `testing.yml` (override per env under `app_testing.notifications.email`) + `SMTP_*` env vars | After every AI test run, pass or fail |

## 14. Production safety

`production` environments have a `safety` block:

```yaml
safety:
  require_confirmation: true   # interactive "Continue?" prompt (skipped on CI)
  require_ci: false            # true = refuse to run outside CI
  allowed_branches: ["main"]   # wildcards allowed, e.g. "release/*"
```

## 15. CI/CD (GitHub Actions)

Two manual workflows (Actions → *Android Distribution* / *iOS TestFlight Distribution* → Run workflow → pick environment). Each runs `doctor` then `distribute`.

Secrets to create in the repository:

| Android | iOS |
|---|---|
| `FIREBASE_TOKEN` (needed for AI tests) | `APP_STORE_CONNECT_KEY_ID` |
| `FIREBASE_SERVICE_ACCOUNT_JSON` (full JSON, written to a temp file) | `APP_STORE_CONNECT_ISSUER_ID` |
| `FIREBASE_ANDROID_<ENV>_APP_ID`, `FIREBASE_ANDROID_<ENV>_GROUPS` | `APP_STORE_CONNECT_KEY_CONTENT` (raw `.p8`, written to a temp file) |
| `FIREBASE_TEST_USERNAME`, `FIREBASE_TEST_PASSWORD` (optional) | `APPLE_TEAM_ID` |
| | `MATCH_GIT_URL`, `MATCH_GIT_BRANCH`, `MATCH_PASSWORD` (match only) |

Repository variable `VERSION_NAME` is optional. `GITHUB_RUN_NUMBER` is used as the build number automatically.

## 16. Troubleshooting

| Symptom | Cause / fix |
|---|---|
| `403 PERMISSION_DENIED` → *"Firebase App Testing Agent test execution failed: Invalid request"* | The App Testing agent rejects **service accounts**, even with every IAM role. Use `FIREBASE_TOKEN` from `firebase login:ci` with the account that opted in. Also confirm the project owner opted in and the Tool Results API is enabled. |
| Manual testers did not receive the build | Group alias in `FIREBASE_ANDROID_<ENV>_GROUPS` must match the alias in Firebase exactly. With AI tests on, the framework distributes first (see section 10). |
| `Test Case <id> not found` | ID in `test_case_ids.yml` must match the console ID and belong to the same Firebase app. |
| AI test fails after login / sees blank screen | `FLAG_SECURE` is enabled in the app for that screen. |

| Local `gcloud` fails with "Python was not found" | Install Python or use the Cloud Console; not needed by the framework. |
